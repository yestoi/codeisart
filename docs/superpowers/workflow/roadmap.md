# Roadmap — wall arcade
**End goal:** A camera-and-microphone arcade for the two-panel LED wall that a stranger at a festival is playing within ten seconds of walking up, unprompted: the attract director shows a mirror of them, a wordless hand-up pictogram invites them, a game starts at once, the three-door menu is opt-in, and the session ends when they leave. Every game is verifiable headlessly on the Mac from scripted and recorded inputs, producing contact sheets, GIFs and feel metrics an agent can judge, with no game code that knows which machine it runs on. 128x32 is the design layout, chosen for two-player side-by-side play, and 64x64 is first-class for single-player games and square visuals. The arcade runs on its own Raspberry Pi 5 driving the spare Colorlight 5A-75E with the raw Colorlight backend, leaving the show Pi 4 untouched. The game list is the one the owner accepted from the review: Copy Me as the hero, Pong, Quick Draw, Dodge, Tug, Flap, Swat, Paint, Strongman and Freeze, with life, beat and the puppet mirror in the attract catalog.

Source documents: the arcade spec as amended by spec revision 3, the core plan with its amendments, and docs/superpowers/reviews/2026-09-26-arcade-adversarial-review.md (sections 6, 7, 10a).

## Carried fixes
C1-C3 and C5-C9 closed in it02 (3017693); C4 closed in it01's report.
- C10 (it02 plan review N5, orchestrator M3 note) Cursor and hold robustness for M3 (core Tasks 8 and 9): the body cursor is stateless and flips hands when the raised wrist drops out (about 15% of captures at spec 6.4 noise), so consumers need grace or hysteresis. `both_hands_up` holds on only 71% of captures under spec noise, with runs of 3+ missed captures longer than `Hold(grace=0.25)`, so a 3 s exit hold resets often: size the exit grace per capture and test it under `degrade`.
- C11 (it02 plan review N11, spec gap) `Blob` has no id or velocity, which M3's presence and NEAR logic and Paint need. Resolve in the M3 plan: add them per the spec's intent, or raise a spec question if the intent is unclear.
- C12 (it02, Important; must land before core Task 8) `Sensed` and `Audio` accept positional arguments, and the core plan's revision-2 calls are positional in the old field order (Task 8 `sense()` line 2884, Task 12 `decode` lines 3659 and 3661, Task 14 line 4157, Task 18 `record` line 5267): `Sensed(t, bodies)` silently puts bodies in `camera_t`. Make every `Sensed` field after `t`, and every `Audio` field, keyword-only; every existing call already uses keywords. Every later producer (`decode` in Task 12, not Task 7 as the it02 plan's forwarded note says) must call `place()`, because `in_zone` defaults to True.
- C13 (it02) `degrade` and `shake` silently fall back to the default calibration: a scene built with a custom zone is re-placed against the default one. Carry the calibration on the scene or require it explicitly, with a test for `degrade`.
- C14 (it02) With one shoulder and no hips, `torso` is 0: the raise line collapses onto the shoulder, `scale` is 0 and `reach` falls back to the box. Use the nose raise line when `torso == 0`, with a test.
- C15 (it02) Actor body ids collide (`crowd` always starts at 100; `scene` uses the list index): `scene` raises on duplicate ids, and `crowd` takes an id base. `degrade` keys noise on the id, and M3's player lock re-acquires by id.
- C16 (it02, minor) Guard rails: `Blob` coordinates are unclamped (`headlamps` crosses x -0.05..1.05), so either clamp at construction or make M3's `to_wall` clamp; `tempo(0)` raises ZeroDivisionError (raise ValueError); `_noisy` keeps the clean `box` and `scale`, so document or degrade them.

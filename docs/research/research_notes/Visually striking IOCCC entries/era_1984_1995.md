# Visually striking IOCCC winners, 1984-1995 (for "Code is Art, A.I. is not")

Method note (applies to every "[build test]" citation below): I shallow-cloned the official winner repo (github.com/ioccc-src/winner, HEAD 31bd35c, 2026-09-28), which is the source of www.ioccc.org, and read each entry's README.md, `.entry.json` (award name) and source. I then built every 1984-1995 entry with the repo's own Makefiles (`make all CC=gcc`) inside `linux/arm64` Docker containers running **gcc 12.5** (≈ Raspberry Pi OS Bookworm) and **gcc 14.4** (≈ Trixie), and ran the visual candidates with timeouts; pty-driven entries were run under `script` with an 80x24 pty and the captured byte stream was replayed through the `pyte` VT emulator to see the final screen. This is aarch64 Linux like a Pi 4, but it was emulated in Docker on an Apple-silicon Mac, not on real Pi hardware. Repo Makefiles compile with `-Wall -Wextra` plus per-entry `-Wno-...` silencers and usually `-std=gnu89/gnu90`.

## Q1. Which 1984-1995 winners are most famous for visual output or source shape?

### Takeaway
The judges gave a visual award to 11 entries in this era: "Best layout" (1986/marshall, 1987/westley, 1988/westley, 1989/roemer, 1990/westley, 1994/schnitzi, 1995/heathbar), "Best visuals" (1988/isaak) and "Best output" (1991/buzzard, 1992/imc, 1995/cdua). Several other entries also have a notable shaped source or animated output: 1984/anonymous (the tattoo), 1991/westley, 1992/westley, 1993/rince, 1994/shapiro and 1995/dodsond1. The ranked shortlist is at the end of this section.

### Cited Findings

**Award names (from each entry's `.entry.json` in the official repo):**
- Best layout: 1986/marshall, 1987/westley, 1988/westley, 1989/roemer, 1990/westley, 1994/schnitzi, 1995/heathbar. Best visuals: 1988/isaak. Best output: 1991/buzzard, 1992/imc, 1995/cdua. Best X11 graphics / Best X program / Most obfuscated X program / Best X11 program: 1991/davidguy, 1992/kivinen, 1993/jonth, 1994/tvr. — [ioccc-src/winner repo](https://github.com/ioccc-src/winner); [ioccc.org years](https://www.ioccc.org/years.html)

#### Ranked shortlist (best overall fit for "portrait + live run on the 80x23 mono wall" first)

**1. 1995/cdua — Carlos Duarte — "Best output"** — [ioccc.org](https://www.ioccc.org/1995/cdua/index.html)
- What it does: author says it "generates a maze, and then solves it, all this being seen by the user"; judges: "the basis of an a-maze-ing screen exerciser." — [1995/cdua](https://www.ioccc.org/1995/cdua/index.html)
- Why it's visual: you watch a full-screen `#` maze get carved out live, then a `.` trail searches and backtracks through it to the exit. It uses ANSI cursor addressing (`\033[%d;%dH`) and clear screen (`\033[2J`). Its buffer is `b[1841]` = 80x23+1, so **it was designed for exactly an 80x23 screen**. — source in [repo](https://github.com/ioccc-src/winner/tree/master/1995/cdua); [build test]: final screen was a 79-col x 21-row maze with a solved path and "Done!!" on row 23.
- Source as art: 2/5 (a dense 16-line block, not shaped). Output as art: 5/5.
- Feasibility: **excellent**. Terminal only, no color. Input: waits for one `<RET>` ("<RET> to begin...") after generating the maze, so feed `\n`. The judges note it may occasionally ask for `<RET>` a second time ("a feature not a bug"), so feed a few newlines. — [bugs.md](https://www.ioccc.org/bugs.html#1995_cdua). Built on arm64 gcc 12 and 14 with 1 warning. The whole run, from generation to solved, finished inside 25 s at the repo's default `SLEEP=3000` (`-DZ=3000`), which is tunable in the Makefile [build test]. It is a cursor-addressed update, not a full-screen strobe, so there is little flash risk. Needs ≥23 rows, so the 15-row Reduced tier breaks it (the maze size is hard-coded).

**2. 1992/imc — Ian Collier — "Best output"** — [ioccc.org](https://www.ioccc.org/1992/imc/index.html)
- What it does: "This is a Mandelbrot/Julia drawer." Its default output is a Sun raster file, but "the program may be asked to produce text output instead", using up to 16 grey shades from the string `" .:';+<?F7RQ&%#*"`. — [1992/imc README](https://www.ioccc.org/1992/imc/index.html)
- Source as art: **5/5**. The source is laid out as the Mandelbrot set's silhouette (cardioid plus bulb), and the judges quip "the source (layout) is self-documenting!" The author also arranged macro names to spell "Ian Colliers Obfuscated C Code". — [1992/imc](https://www.ioccc.org/1992/imc/index.html)
- Output as art: 4/5. [build test] `./imc -text -size 78 22 -mask 15 -limit 15 2>/dev/null` gave a full-screen 78x22 shaded Mandelbrot that looks good in one colour. The plain `./imc -text` default gave a 63x23 two-tone banded image.
- Feasibility: very good. Terminal text, arguments only, no stdin. It prints progress dots on stderr, so redirect `2>/dev/null`. Built on arm64 gcc 12 and 14 with 1 warning. The author warns it "naughtily declares the first argument to main() as a long" and assumes `long` sizes for the raster header, and the judges' fixed version patched the `exit()` and `argc` issues. Text mode worked correctly on 64-bit ARM [build test]. The image is static and appears in under a second, so for 40 s of show the harness should chain several zooms/Julia sets (e.g. the `-julia`/`-centre` examples in try.sh).

**3. 1991/buzzard — Sean Barrett — "Best output"** — [ioccc.org](https://www.ioccc.org/1991/buzzard/index.html)
- What it does: a first-person 3D ASCII maze walk. Commands are `f` (forward), `r`/`l` (turn) and `^D`, and "the new view will be drawn after all the moves." The maze is read from a file, by default **its own source code**. — [1991/buzzard](https://www.ioccc.org/1991/buzzard/index.html)
- Source as art: 4/5. The source's whitespace is itself the maze map (`fopen(x-1?a[1]:__FILE__,"r")`), so the portrait literally is the level. Output as art: 5/5 (wireframe corridors made of `|`, `/`, `\`, `-`).
- Feasibility: good, with a wrapper. [build test] each view is exactly **23 lines** (the loop runs y=-11..11), about 47 columns wide, and uses tabs. It needs canned input fed with delays, e.g. `(for m in f f r f l f ...; do echo $m; sleep 1.5; done) | ./buzzard`, to make it an animation. Built on arm64 gcc 12 and 14 with 1 warning. The source file must be present in the working directory, or it "will very likely crash". — [bugs.md](https://www.ioccc.org/bugs.html#1991_buzzard). It does not fit the 15-row Reduced tier.

**4. 1993/rince — James Bonfield — "Most well rounded"** — [ioccc.org](https://www.ioccc.org/1993/rince/index.html)
- What it does: CABBAGE, a "Cellular Automata Based, Beautifully Abysmal Game Environment". With no arguments "it will default to using its own datafile (the source code in fact). This happens to be a game of Space Invaders." Data files for Breakout and other games are included. — [1993/rince](https://www.ioccc.org/1993/rince/index.html)
- Source as art: 4/5. The Space Invaders playfield (a `#` border with `<`/`>` alien rows) and the automaton rule tables sit visibly in the source. Output as art: 4/5.
- Feasibility: good. [build test] under a pty with **no input**, the aliens march and `v` bombs rain down on their own. The playfield is 40x20 and fits the 23-row screen, though not 15 rows. It uses curses (needs `libncurses-dev` on the Pi) and built on arm64 gcc 12 and 14 with 0 warnings. The judges say "There is no end of game checking function", so it runs until killed, which suits the 40 s cutoff. — [bugs.md](https://www.ioccc.org/bugs.html#1993_rince)

**5. 1992/westley — Brian Westley — "Best small program"** — [ioccc.org](https://www.ioccc.org/1992/westley/index.html)
- What it does: "Run the program with your latitude & longitude as integer arguments; it will produce a map made up of '!' with the given position marked". It is a Mercator world map at 5° x 10° resolution. — [1992/westley](https://www.ioccc.org/1992/westley/index.html)
- Source as art: 3/5 (a small 12-line blob with `H E L L O,  W O R L D!` embedded in the data string). Output as art: 4/5. A world map with the burn's own location marked is a nice site-specific touch.
- Feasibility: very good. Arguments only. [build test] the output is 14 lines x 80 columns. The judges note "as long as the terminal columns is >= 80 it will display properly." — [bugs.md](https://www.ioccc.org/bugs.html#1992_westley). Caution: it prints exactly 80 characters then `\n`, so the wall's terminal must do VT100/xterm "pending wrap" or every row gets a blank line after it. Built on arm64 gcc 12 and 14 with 0 warnings. The output is static.

**6. 1985/shapiro — Carl Shapiro — "Grand Prize - Most well rounded in confusion"** — [ioccc.org](https://www.ioccc.org/1985/shapiro/index.html)
- What it does: prints a random maze. The judges say "simply a**maze**ing! Run this program without arguments". — [1985/shapiro](https://www.ioccc.org/1985/shapiro/index.html)
- Source as art: 1/5 (a 9-line block). Output as art: 3/5.
- Feasibility: excellent fit. [build test] the output is **exactly 23 lines, max 79 columns** (the code has `C 39`, `R=22`). There is no input, and it built with 0 warnings on arm64 gcc 12 and 14. It prints instantly and statically. It uses `rand()` without a seed, so the maze is the same every run unless patched.

**7. 1994/shapiro — Andrew Shapiro — "Most well rounded obfuscation"** — [ioccc.org](https://www.ioccc.org/1994/shapiro/index.html)
- What it does: the author says the source "is mostly comments, formatted in the shape of a **clock**". The theme is "This time (everything) is not where it should be." — [1994/shapiro](https://www.ioccc.org/1994/shapiro/index.html)
- Source as art: **5/5** (a large round clock face made of letter-noise comments with hands of code). Output as art: 2/5. [build test] it draws a small boxed hours/minutes/seconds readout in the top-right corner of the screen via ANSI cursor positioning and updates it every second, forever.
- Feasibility: good. No input, 0 warnings on arm64 gcc 12 and 14. It must run in the directory holding the source, since it `fopen(__FILE__)`s itself and "will likely crash" otherwise. — [bugs.md](https://www.ioccc.org/bugs.html#1994_shapiro). This is a strong portrait with a modest live run.

**8. 1994/horton — Mary Ann Horton — "Best utility"** — [ioccc.org](https://www.ioccc.org/1994/horton/index.html)
- What it does: "Run it with any 4 numeric arguments, e.g. ./horton 3 2 1 0." It plots the cubic a·x³+b·x²+c·x+d. The judges ask how "this program prints, for a given slope, the right character." — [1994/horton](https://www.ioccc.org/1994/horton/index.html)
- Source as art: 3/5 (the code is spread around the edge of a rectangle, like a plot frame). Output as art: 3/5 (a smooth curve drawn with slope-matched characters in a box).
- Feasibility: good. Arguments only, 0 warnings. [build test] the output is 24 rows x 79 columns, one row more than the wall. The first two and last three rows are blank, so trimming them or tolerating one scroll works. The output is static, so the harness could cycle through the six parameter sets in try.sh.

**9. 1984/laman — Mike Laman — "Third Place"** — [ioccc.org](https://www.ioccc.org/1984/laman/index.html)
- What it does: prints the integers 1..N as a square spiral. [build test] `./laman 100` gave a 10x10 spiral.
- Source as art: 3/5 (code chopped into neat tab-aligned columns, like a table). Output as art: 2/5.
- Feasibility: good. Arguments only, 9 warnings. Each cell is printed with `"%-4d"`, so by arithmetic from the code, `./laman 400` would give 20 rows x 80 columns (not run).

**10. 1989/tromp — John Tromp — "Best game"** — [ioccc.org](https://www.ioccc.org/1989/tromp/index.html)
- What it does: "a character terminal version of the TETRIS game. It runs on a VT100 compatible terminal". Blocks are drawn in reverse video with `\033[7m`. — [1989/tromp](https://www.ioccc.org/1989/tromp/index.html)
- Source as art: 1/5. Output as art: 4/5, if the wall renders reverse video.
- Feasibility: **poor as-is**. [build test] it builds, but **segfaults on arm64 Linux** right after drawing the well. The cause is likely `sigaction(14,v,0)`, where `v` is a 3-long array pretending to be a `struct sigaction`. Swapping in `signal()` stops the crash, but then nothing drops, because glibc's `signal()` sets SA_RESTART and the design relies on SIGALRM interrupting `getchar()`. So it needs a proper `sigaction` patch without `SA_RESTART`. With no input the pieces would just stack in the middle until game over. It also runs `stty cbreak` and writes a `HI` score file.

**11. 1988/phillipps — Ian Phillipps — "Least likely to compile successfully"** — [ioccc.org](https://www.ioccc.org/1988/phillipps/index.html)
- What it does: prints the full lyrics of "The Twelve Days of Christmas" (65 lines, max 68 columns) [build test]. The judges: the source "looked like what you would get by pounding on the keys of an old typewriter at random."
- Source as art: 3/5. Output as art: 2/5 (scrolling text). 0 warnings. Famous, but the output is a lyric, not a picture.

**12. 1990/baruch — Baruch Nissenbaum & Doron Osovlanski — "Best small program"** — [ioccc.org](https://www.ioccc.org/1990/baruch/index.html)
- What it does: an N-queens solver that reads N (4..99) from stdin. "For each solution the chess board and the place of the queens is printed". — [1990/baruch](https://www.ioccc.org/1990/baruch/index.html)
- Source as art: 1/5 (6 lines). Output as art: 2/5 (scrolling boards). Feasibility: canned input `echo 8 |`, 1 warning. Some visual interest as boards scroll by, but it is not a strong piece.

#### Portrait-first entries (striking source, weak or trivial output)
- **1988/westley, "Best layout"**: the famous circle of `_-_-_` whose area computes pi. It prints just `3.141` [build test]. The repo's fixed version replaces the `-_` → `--` token-pasting trick, which modern preprocessors do not do, and keeps the original as `westley.alt.c`. 0 warnings. **The best portrait in the era**, but a 1-line run. — [1988/westley](https://www.ioccc.org/1988/westley/index.html)
- **1987/westley, "Best layout"**: a mirror-symmetric "C ink blot" palindrome that prints `Able was I ere I saw elbA`. 0 warnings. — [1987/westley](https://www.ioccc.org/1987/westley/index.html)
- **1986/marshall, "Best layout"**: the source is a picture, and "This program prints the name of the picture" (`choo choo`, a train). [build test] the main `marshall.c` printed nothing (rc=1) on arm64 gcc. `make alt` (`marshall.alt.c`) printed `choo choo`. The repo documents optimizer- and compiler-dependent breakage in compilers.html. — [1986/marshall](https://www.ioccc.org/1986/marshall/index.html)
- **1989/roemer, "Best layout"**: a pi-themed layout ("more here than meets the PI") that computes digits of pi. [build test] **it segfaulted on arm64 gcc 14** at both -O3 (Makefile) and -O0. I suspect `--*__3_14` writing into the string literal "3.1415" (read-only on modern systems), but that is unverified. — [1989/roemer](https://www.ioccc.org/1989/roemer/index.html)
- **1990/westley, "Best layout"**: a "Picking the Daisy" simulation written to read like a love letter. It prints `loves me` / `loves me, not` lines. 0 warnings. — [1990/westley](https://www.ioccc.org/1990/westley/index.html)
- **1991/westley, "Grand Prize"**: "The code is written as a tic-tac-toe grid; moves are carried out within the code". The program prints its own source with the moves added, and you recompile to continue. [build test] its output lines reach **89 columns** (too wide for 80), and a game needs compile-run cycles. It is a great portrait. — [1991/westley](https://www.ioccc.org/1991/westley/index.html)
- **1995/dodsond1, "Most humorous"**: an English-to-Pig-Latin filter. The author: "Most obviously, the shape of the program", an outline drawn in `X`s (it looks like a pig's face with ears, my reading of the ASCII art, not confirmed by the author). [build test] **on arm64 Linux it loops forever printing garbage**, because `char` is unsigned on Linux/aarch64 and the EOF check `(atinla+1)` never goes false. Building with `-fsigned-char` fixes it: "Code is art and AI is not" → "Odeca iswa artwa andwa AIwa iswa otna". Needs canned stdin. — [1995/dodsond1](https://www.ioccc.org/1995/dodsond1/index.html)
- **1995/heathbar, "Best layout"**: a source built almost entirely from `#define`d variants of the word `main` (`MAin`, `mAIN`, `Ma1N`...) arranged as a large block figure. The judges: "the main effect of the source was self documenting". It adds two numbers (`./heathbar 1234 999` → 2233). — [1995/heathbar](https://www.ioccc.org/1995/heathbar/index.html)
- **1995/savastio, "Most obfuscated syntax"**: "an artistic code layout" (identifiers made only of `l` and `1` in a block-letter shape). It computes big factorials from stdin. — [1995/savastio](https://www.ioccc.org/1995/savastio/index.html)
- **1994/schnitzi, "Best layout"**: flips a text file along its diagonal. The source contains vertical text, and running it on itself (`./schnitzi < schnitzi.c`) prints a transposed program with legible block letters. It uses `gets()`, and the macOS linker warns about that. — [1994/schnitzi](https://www.ioccc.org/1994/schnitzi/index.html)
- **1984/anonymous, "Dishonorable Mention"**: a "hello, world" variant. "In 2005 someone by the name of Thomas Scovell got a tattoo of this entry." A culturally famous piece of IOCCC source, only 2 lines. — [1984/anonymous](https://www.ioccc.org/1984/anonymous/index.html)
- **1988/isaak, "Best visuals"**: prints the periodic table of the elements as a boxed ASCII chart. The repo's `isaak.output.txt` is about 73 columns x ~40 rows, **too tall for 23 rows** (it would scroll). The source is not shaped. — [1988/isaak](https://www.ioccc.org/1988/isaak/index.html)

### Inferences
- The strongest pairings of "portrait + live run" in this era are **1992/imc** (Mandelbrot-shaped source → Mandelbrot output), **1991/buzzard** (the maze source is the maze you walk) and **1993/rince** (the game board is in the source and plays itself). 1995/cdua has the best live output but a plain source.
- For a pure portrait, 1988/westley (the pi circle) and 1994/shapiro (the clock) are the most immediately readable shapes. Both have weak runs, though 1994/shapiro at least updates live.

### Gaps
- I did not find community write-ups, Hacker News threads or YouTube videos ranking these entries by visual fame. The fame ranking above rests on the judges' award names and README remarks, not on popularity data.
- 1995/heathbar's figure and 1995/dodsond1's outline: I did not confirm what the shapes are meant to depict beyond the README text.

## Q2. Which produce terminal-only output that fits 80x23?

### Takeaway
Verified to fit 80x23 in a terminal: 1995/cdua (designed for exactly 80x23), 1985/shapiro (79x23), 1991/buzzard (23-line frames), 1993/rince (40x20, curses), 1992/imc (`-size 78 22`), 1992/westley (80x14, needs pending-wrap), 1994/shapiro (corner widget). 1994/horton needs a 1-row trim. Too wide or too tall: 1991/westley (89 cols) and 1988/isaak (~40 rows). Needs X11 or other graphics, so portrait-only: 1991/davidguy, 1992/kivinen, 1993/jonth, 1993/cmills, 1994/tvr and 1995/leo (PostScript).

### Cited Findings
- 1995/cdua's buffer `b[1841]` (80x23+1) and ANSI addressing; the final screen was 79 cols x 23 rows. — [1995/cdua source](https://github.com/ioccc-src/winner/blob/master/1995/cdua/cdua.c); [build test]
- 1985/shapiro prints 23 lines, max 79 columns. — [build test]; [1985/shapiro](https://www.ioccc.org/1985/shapiro/index.html)
- 1991/buzzard frames are 23 lines (y=-11..11) and about 47 columns. — [build test]; [1991/buzzard](https://www.ioccc.org/1991/buzzard/index.html)
- 1993/rince's Space Invaders board is 40x20 (`41 20` header in the source) and animates without input under curses. — [build test]; [1993/rince](https://www.ioccc.org/1993/rince/index.html)
- 1992/westley needs at least 80 columns; its output is 80x14. — [bugs.md](https://www.ioccc.org/bugs.html#1992_westley); [build test]
- 1994/horton prints 24 rows x 79 columns. — [build test]
- 1991/westley output lines reach 89 characters. — [build test]
- **X11-only, fail the wall (portrait-only candidates):**
  - 1991/davidguy, "Best X11 graphics": "a fully-functional X client" that talks raw X protocol over a socket and "plays Conway's Game of Life in the root window's bits". — [1991/davidguy](https://www.ioccc.org/1991/davidguy/index.html)
  - 1992/kivinen, "Best X program": "X Entertainment Kit", three early video games including Space Invaders, for X11R5. — [1992/kivinen](https://www.ioccc.org/1992/kivinen/index.html)
  - 1993/jonth, "Most obfuscated X program": "jon's t(h)etris for the X Window System". It "will not work on machines where sizeof(int)!=sizeof(void *)", which rules out 64-bit ARM too. — [1993/jonth](https://www.ioccc.org/1993/jonth/index.html)
  - 1993/cmills, "Bill Gates Award": an X program in which windows break "based on its kinetic energy". — [1993/cmills](https://www.ioccc.org/1993/cmills/index.html)
  - 1994/tvr, "Best X11 program": "Interactive Fractals for X Window System", with Mandelbrot and Julia pairs animated by the mouse. — [1994/tvr](https://www.ioccc.org/1994/tvr/index.html)
- 1995/leo, "Best use of obfuscation": its output starts with `%!` PostScript (`puts("%!\n/S{ 0 setlinewidth}...")`), and the judges mention Ghostscript clearing the screen after each image, so it needs a PostScript viewer, not a terminal. — [1995/leo](https://www.ioccc.org/1995/leo/index.html)
- 1995/dodsond2, "Best game": an "Interactive 3D Maze" in curses driven by `hjkl`/`u`/`d`. It needs live keystrokes, and with no input it would show one static view. — [1995/dodsond2](https://www.ioccc.org/1995/dodsond2/index.html)

### Inferences
- The Reduced 15-row tier rules out cdua, shapiro-1985, buzzard, rince and full-size imc. Of the strong visuals, only imc can be resized (`-size 78 14`) to fit 15 rows.
- None of the shortlisted entries use ANSI colour, so the single-phosphor wall loses nothing. 1989/tromp relies on reverse video (`\033[7m`), which the wall's emulator would need to support.

### Gaps
- I did not test brightness or bold rendering, since that depends on the wall's emulator.
- 1995/leo: I did not render the PostScript, so the image content is unverified.

## Q3. Which build cleanly on modern 64-bit gcc, or have fixes in the current repo?

### Takeaway
With the modern repo's Makefiles, **110 of 111 entries from 1984-1995 built on arm64 Linux with both gcc 12.5 and gcc 14.4**. The only failure was 1990/stig, a deliberate rule-abuse entry. Building does not guarantee running correctly on aarch64, though. 1989/roemer and 1989/tromp segfaulted, 1986/marshall's main version printed nothing, and 1995/dodsond1 looped forever because `char` is unsigned on Linux/ARM. Use the repo Makefiles (they set `-std=gnu89/gnu90`). A bare `gcc` under gcc 14 turns implicit-int and implicit-declaration into hard errors.

### Cited Findings
- [build test] `make all CC=gcc` built 110 of 111 entry directories (1984-1995) on gcc 12.5 and gcc 14.4 arm64. Only 1990/stig failed. Warning counts for the shortlist (gcc 14): cdua 1, imc 1, buzzard 1, rince 0, westley-1992 0, shapiro-1985 0, shapiro-1994 0, horton 0, laman 9, tromp 2.
- [build test] compiling 1989/roemer and 1995/dodsond1 with plain `gcc -std=` default under gcc 14 failed with `error: type defaults to 'int'` and `error: implicit declaration of function` (e.g. `write`, `puts`, `getchar`). The repo Makefiles avoid this with `-std=gnu89/gnu90` and explicit `-include stdio.h` and similar.
- The repo's Makefile convention: `CWARN= -Wall -Wextra ${CSILENCE}` with per-entry `-Wno-*` flags, and `CSTD= -std=gnu90` (e.g. 1995/cdua). This satisfies "-Wall, not -w", but the silencers hide many warnings. — [1995/cdua Makefile](https://github.com/ioccc-src/winner/blob/master/1995/cdua/Makefile)
- The repo holds fixed versions (`<name>.c`) alongside originals (`<name>.orig.c`) and often an `.alt.c`. The READMEs say, e.g., "this version is a fixed version for modern C compilers" (1988/westley) and "In 2023 this entry was updated to allow most ANSI C compilers to compile the code" (1991/rince). — [1988/westley](https://www.ioccc.org/1988/westley/index.html); [1991/rince](https://www.ioccc.org/1991/rince/index.html)
- 1995/cdua "did not originally compile under macOS and after it did compile under macOS, it crashed. These problems were fixed." — [bugs.md](https://www.ioccc.org/bugs.html#1995_cdua)
- 1994/shapiro "was fixed to not use -1 for the return value of getc()". — [bugs.md](https://www.ioccc.org/bugs.html#1994_shapiro)
- 1992/imc's original "assumed that exit(3) returned a value" and "declared argc to be a long", both fixed in `imc.c`. — [1992/imc](https://www.ioccc.org/1992/imc/index.html)
- Runtime failures on arm64 [build test]:
  - 1989/roemer segfaults (rc 139).
  - 1989/tromp segfaults. The `sigaction` hack needs a patch, and a naive `signal()` patch leaves pieces frozen because of SA_RESTART.
  - 1986/marshall's `marshall.c` returns 1 with no output, while `marshall.alt.c` works. The repo discusses gcc/clang optimizer conflicts. — [1986/marshall compilers notes](https://www.ioccc.org/1986/marshall/compilers.html)
  - 1995/dodsond1 loops forever unless built with `-fsigned-char`.

### Inferences
- **Signed vs unsigned char is the ARM-specific trap.** Apple-silicon macOS uses signed `char`, but Linux/aarch64 (the Pi) uses unsigned `char`. A fix tested only on a Mac can still hang on the Pi. Build every chosen entry on the Pi itself, or in an arm64 Linux container, and consider `-fsigned-char` as a blanket safety flag for EOF-in-char idioms.
- The top four shortlist entries (cdua, imc, buzzard, rince) plus 1992/westley and 1985/shapiro all built and ran correctly on arm64 Linux with the repo Makefiles, with no patching.

### Gaps
- Not tested on real Raspberry Pi 4 hardware or on the actual wall terminal emulator. The Docker arm64 containers are a close proxy, not proof.
- 1989/roemer's crash cause is my hypothesis only (a string-literal write). Not debugged.
